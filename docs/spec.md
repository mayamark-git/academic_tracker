# Academic Tracker 仕様書

## 1. 文書の位置づけ

本書は提出用に、現在のソースコードとREADMEに基づいて整理した仕様書です。企画時の背景・構想は [SPEC_CONTEXT.md](../SPEC_CONTEXT.md) を参照してください。両者の記述が異なる場合、実装状況については現行コードを正とし、未実装の構想を実装済みとして扱いません。

## 2. 背景と目的

修士論文等の研究では、論文の収集・読解、研究者や学会の情報整理、最新情報の継続確認が別々のサービスやファイルに分散しやすくなります。本アプリは、文献情報と研究メモをローカルでまとめ、検索・PDF管理・AIによる整理を通じて先行研究の把握を支援します。

## 3. 想定利用者

- 学術文献や研究者情報を個人で整理したい学生・研究者
- Windows上でローカルアプリとして研究資料を管理する利用者

## 4. 提供形態・技術構成

- Web UI: Python / Streamlit
- 永続化: SQLite（WALモード）
- 論文検索・PDF取得: CiNii等の外部サービス、Unpaywall/J-STAGE等のリンク探索
- AI機能: Google GenAI SDK。APIキーは環境変数で設定
- PDF本文抽出: pypdf（OCRは対象外）
- 起動: `start_app.bat` または `python -m streamlit run app.py`
- DBパス: `ACADEMIC_TRACKER_DB_PATH`。未設定時は作業ディレクトリの `papers.db`

## 5. 機能要件

### 5.1 論文一覧

- 論文の書誌情報、抄録、DOI、AI要約、メモ、既読状態を一覧・編集する。
- 著者名・キーワードを対象にCiNiiから論文を取得し、重複を避けてDBに保存する。
- キーワード、DOI有無、既読状態、並び順等で絞り込み・表示する。
- CiNii、J-STAGE、Google Scholar、DOI等へのリンクを提供する。
- PDFを手動登録、または対応する公開PDFを取得し、論文レコードに紐付ける。
- PDFからテキストを抽出し、Geminiで研究レビュー向けの要約を生成できる。
- PDF・要約の処理に失敗した場合、論文書誌情報や取得済みPDFを保持し、失敗内容を利用者に示す。
- 論文のDBバックアップと論文一覧CSVのエクスポートを提供する。バックアップにPDF本体は含めない。

### 5.2 自分の論文から関連文献を探す

- 基準論文PDFから研究課題、キーワード、概念、参考文献中の研究者候補を抽出する。
- 抽出結果を確認・編集し、キーワード・概念と研究者名を用いてCiNii候補を検索する。
- 候補を重複整理し、AIの関連度評価と理由を履歴として管理する。
- 評価の未完了・失敗候補を確認し、再評価できる。
- 選択候補を書誌情報のみで登録するか、PDF取得・要約を試みて登録する。
- 外部APIへの送信対象や検索件数上限等の運用条件はREADMEに記載する。

### 5.3 研究テーマ情報

- 研究テーマと検索語を登録・削除する。
- CiNiiの論文情報およびGoogle検索で得た公的機関等の情報を収集し、要約・出典とともに履歴保存する。
- 前回実行から7日以上経過したテーマを画面表示時に収集対象とし、手動での再収集も可能にする。
- 画面を開いていない間の定期実行は、任意のWindowsタスクスケジューラ設定を利用する。

### 5.4 研究者プロファイル

- 研究者名、所属・専門分野、学問的潮流、概念、所属学会、メモ等を管理する。
- AIによる情報取得・補完と手動編集を提供する。
- 研究者を複数列に配置し、表示順や列名を管理する。

### 5.5 関連学会アーカイブ

- 学会名、関連研究者、分類、公式URL、メモ、検討対象フラグを管理する。
- 研究者プロファイルと学会情報を双方向に同期する。
- 学会情報を外部検索し、結果をメモに加える。

### 5.6 著者・キーワード管理

- CiNii自動収集に用いる対象研究者と検索キーワードを追加・削除する。
- 研究者追加時にプロフィールの初期レコードを作成する。

## 6. データ要件

- SQLiteに論文、対象研究者、研究者プロフィール、学会、検索キーワード、設定、関連文献探索履歴、研究テーマ・収集履歴を保存する。
- DB初期化・スキーマ更新は繰り返し実行可能で、既存データを保持する。
- PDFは原則 `pdf_files/` に保存し、個人研究データとしてリポジトリには含めない。
- 利用者操作のアクセスログ／利用ログをCSVに記録する機能は現時点で実装されていない。`logs/usage.csv` は作成せず、ログ要件が決まった時点で同意・保存内容・保持期間を定義して実装する。

## 7. 非機能要件・制約

- 個人利用を前提としたローカルアプリであり、現時点で認証・マルチユーザー機能はない。
- APIキーは `.env` 等のローカル環境変数で管理し、公開リポジトリへ登録しない。
- 外部APIの停止・クォータ・ネットワーク状況により検索やAI処理が失敗し得る。失敗を画面に表示し、再実行可能にする。
- PDFの画像OCR、PDF本体を含むDBバックアップ、アプリ画面を閉じた状態での常時稼働は保証しない。
- 外部AIへ送信される入力（PDF抽出テキスト、論文情報、検索語等）があるため、機密文書・送信を許可しない情報には利用しない。

## 8. 受け入れ確認

- `python -m unittest discover -v` が成功すること。
- 空の一時DBおよび既存スキーマのDBで初期化でき、既存データが保持されること。
- アプリ起動後、論文一覧・関連文献探索・研究テーマ・研究者・学会・設定の各画面へ遷移できること。
- 外部API失敗時に画面が異常終了せず、失敗が表示されること。
- 公開前に `.env`、SQLite DB/WAL、PDF、ローカル生成物がGitに含まれていないこと。
